# M0 / M1 继续对齐交付记录

日期：2026-11-08。沿用现有 Vben web-ele + Nitro Mock，不接入真实 AI、第三方登录、视频生成或支付。

## 本轮补齐

- 项目详情可选本项目图片/Logo 作为封面，也可恢复默认封面；API 校验素材归属和版本。封面引用持久保存，项目卡懒加载图片，失效回退默认封面；删除素材解除封面引用。本地上传内容仍按文档允许的元数据方案处理。
- 新建项目多平台选择时显示裁切风险与安全区域提醒，保留用户所选画面比例。
- 每个文件独立显示 Mock 百分比、提交中/成功/失败/取消状态，支持并行选择、单独取消和全部取消。上传重试复用同一文件与请求内容的幂等键，避免超时重试重复创建。模拟准备阶段可取消，提交后需删除素材。
- 文档素材预览显示模拟解析摘要与来源；视频播放失败提示浏览器不支持格式，可继续保留元数据。
- 报告显式显示保存中/已保存/保存失败及未保存修改；失败保留编辑内容，可重试。
- 痛点可确认真实、标为不适用、加入候选价值线索；显示模拟传播判断，明确不代表投放效果。功能标记不支持保留审核记录，关联痛点提示依据变化。
- 归档项目禁止进入 Studio 编辑；直接调用资料修改接口也会被服务端阻止，恢复后继续。
- 分析任务绑定启动时的资料快照与证据，新增资料并确认新快照不会将运行中任务偷偷切换到新输入。旧快照不能绕过过期门禁；确认新资料不会改写已确认报告的原始内容和版本。

## 复现命令

在 frontend 下运行：

```powershell
pnpm --filter @vben/web-ele run typecheck
pnpm run build:ele
pnpm --filter @vben/backend-mock run build
pnpm exec vitest run apps/backend-mock/utils/creative-video/__tests__ apps/web-ele/src/utils/creative-video
# 先启动前端与 Mock，再执行对应本地端口的浏览器/API 测试
node tests/e2e/m1-smoke.mjs
node tests/e2e/m1-alignment.mjs
node tests/e2e/m1-api-check.mjs
```

专项运行可用 M1_BASE_URL、M1_API_BASE、M1_SCREENSHOT_DIR 指定独立环境。Vite 支持 VITE_MOCK_PROXY_TARGET 指定 Mock 代理。本次使用前端 5556、Mock 15320 和独立状态文件，没有重置用户现有服务。

## 交付边界

本地 JSON 仓储适用于单进程演示；上传文件只持久化元数据，本地文件刷新后需重新选择才能预览。这是两份文档明确允许的 M0/M1 Mock 方案。批量项目操作仍按文档 P1 允许延后，M2～M4 页面继续为占位。浏览器主链路和新增专项通过并不等于逐条穷举了文档的所有异常组合。
