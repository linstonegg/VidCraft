## 0. 给前端团队的执行摘要（必读）

### 0.1 一句话说明产品

用户提供**产品网址 URL**，必要时补充**演示系统访问授权、产品录屏、截图、PDF/Word 产品说明和品牌资料**；AI 深入理解产品，主动发现**最值得传播的价值切口**，策划具有故事、反差、情绪、视觉冲击力的营销视频；用户分阶段审阅产品分析、创意方向、剧本、图文分镜与单镜头视频，满意后再付费生成或确认，最终自动合成为 30/60/120 秒等完整视频。

**不是**：软件操作教学视频、常规功能罗列式广告、只会把网页截图拼成视频的 URL-to-Video 工具。  
**而是**：懂产品、懂用户、懂营销传播的 **AI 创意导演 + 可控视频制片工作台**。

### 0.2 产品独特性与核心设计原则

1. **传播切口优先于剧本**：主动寻找“PDF 简历 → 3D 交互网页”式反常规价值，也寻找真实痛点、结果、身份、愿景等切入点。
2. **用户提供事实，AI 提炼洞察**：网站公开页面、用户授权演示数据、录屏、图片和说明材料需要在“证据/推测”层面区分，不能虚构功能、案例和效果。
3. **创意先于生成**：先形成三个有显著差异的方向，用户确认后再写完整剧本；目标时长应在剧本设计前参与规划。
4. **高成本生成前设审核关卡**：产品理解 → 创意 → 图文分镜 → 低成本整片预演 → 视频片段 → 整片，各阶段均可编辑与确认。
5. **镜头独立版本，旧版永不覆盖**：任何重新生成均为候选新版，用户采用后才变更时间线的正式镜头引用。
6. **生成前报价，额度冻结，结果结算**：Mock 完整模拟账务，实际商业化必须服务端强一致保障。
7. **允许 120 秒整片，不依赖单次模型生成 120 秒**：AI 分解故事节拍和镜头，以短片段、图片动效、真实素材和配音合成完整叙事。
8. **减少无谓操作**：专业审核模式优先，未来预留在预算范围内自动运行的托管模式；确认不意味着无法回退。
9. **前端先以 Mock 跑通真实交互**：所有按钮、提示、状态变更、版本对比、积分结算和异常场景均要可演示，不能只有静态页面。
10. **独立创作布局**：Vben 负责账户/菜单/表单/权限等基础，核心 Studio 采用全屏、视频优先的创作界面，不要套常规后台表格布局。

### 0.3 本阶段必须完成的业务演示

**演示剧本（验收必须能一气呵成）：**

1. 登录测试账号 → 进入项目中心 → 新建项目“3D 数字简历推广片”。
2. 输入演示 URL，补充录屏/图片/Word/PDF（Mock 上传），可切换模拟“需要登录”的场景。
3. AI（Mock）展示“产品理解报告”，标注可证实功能、推测痛点和证据来源；用户修改内容后确认。
4. AI（Mock）提供三个不同创意切口，包括**反常规/认知刷新**、**痛点情绪共鸣**、**视觉奇观/身份表达**；用户选择并微调。
5. 用户要求 120 秒，系统提示“当前创意更适合 30 秒”，可选“完整故事扩写”“多章节影片”“保留短片”，再生成合理的 120 秒故事节拍。
6. 展示带**每镜头参考图、剧情、旁白、字幕、镜头运动、时长、转场、背景音乐**的分镜，编辑镜头 03 并产生新分镜修订版。
7. 通过分镜图片 + 临时配音/简单动效模拟低成本整片预演，调整顺序与时长；确认后进入高成本环节。
8. 单镜头点击“生成视频”，系统展示模型/时长/清晰度/候选数量/预计积分；确认冻结积分，显示异步任务状态，生成候选 V2。
9. 原版 V1 与候选 V2 对比；用户不满意，在 AI 对话框中描述“纸张先破碎再出现人物”，AI（Mock）提出修改计划；再次报价后生成 V3。
10. 审核采用 V3，保留 V1/V2 历史；其他镜头保持不变。可回滚 V1，回滚不扣视频生成积分。
11. 全镜头审核通过 → 点击“合成整片” → Mock 渲染任务完成 → 在完整播放器中预览、局部修改后重新合成 → 导出模拟成片记录。
12. 进入任务中心和积分账单，能看见这次任务的冻结、正式结算、失败释放、账单明细和镜头版本关联。

> **不在本阶段真实执行**：爬取第三方网站、提交演示账号密码、访问内网、视频模型 API、Seedance/可灵调用、真实充值/支付、真正 FFmpeg 合成、真实 SignalR 后端连接。所有上述功能必须有明确的“演示模式”标识与可替换的 API 契约。

## 1. 产品定位、目标用户和衡量指标

### 1.1 项目暂用名称

- 中文：AI 创意营销视频 Agent / AI 产品创意导演。
- 英文：AI Product Creative Director / Creative Marketing Video Agent。
- 技术内部名（建议）：`creative-video-studio`。
- 未来品牌名可变，所有 UI 文案与 Logo 应配置化，禁止业务代码中硬编码正式品牌。

### 1.2 目标用户

| 用户人群 | 核心问题 | 对本产品的期望 |
|---|---|---|
| 独立开发者 | 网站上线但不懂宣传 | URL 输入后即可获得令人惊喜的创意及成片 |
| 小型 SaaS 创业团队 | 没有专职广告策划与剪辑 | 从产品理解到图文分镜可反复审核 |
| 中小企业产品负责人 | 有官网、系统及产品说明但难讲卖点 | 找到最容易被客户感知的价值与痛点 |
| 营销运营/自媒体运营 | 持续需要抖音、视频号、B 站等素材 | 多创意、多比例、多时长、可控预算 |
| 视频制作团队/代理商 | 有制作能力但缺高质量脚本 | 单独交付创意方案、分镜及素材包 |

### 1.3 产品核心目标（与统计口径分离）

- 用户能在不懂提示词工程的情况下，从产品资料走到图文分镜。
- 每次至少能选择 **3 个差异明显**的创意方向，而不是相同剧情换句话术。
- 用户能在视频生成前识别内容错误、修改分镜，避免高价无效重试。
- 任一镜头可独立改动、版本比较、回退、重新计费，不影响已批准的镜头。
- 120 秒等长片通过多镜头合成获得，不直接受单模型时长上限约束。
- 提前为未来真实指标预留：创意方案选择率、修改次数、生成成功率、单镜头成本、整片通过率、复购、观看完成率、点击率、注册转化（**当前 Mock 不展示虚假的真实转化成绩**）。

### 1.4 视频内容的边界

- 支持：故事广告、创意短片、概念动画、情景剧、痛点反转、品牌叙事、产品价值展示。
- 不以“教程、按钮演示、完整操作流程介绍”为核心；真实产品录屏可作为**证实产品能力的素材**或短暂植入的画面。
- 对营销效果不做“必然爆款/保证成交”等承诺。
- 不得凭空声称产品效果、用户评论、价格优势、收益数据。

| 优先级 | 必须建设的页面/能力 | Mock 交付要求 |
|---|---|---|

| P0 | 产品理解报告与人工确认 | 可编辑、证据分级、变更版本 |

| P0 | 时长评估与完整故事脚本 | 30/60/120 秒、冲突提醒、多策略扩写 |
| P0 | 图文分镜工作台 | 图片、台词、动作、时长、转场、批注、版本 |

| P0 | 生成报价/积分冻结与结算 | 动态模拟价格、完整账务流水 |

| P1 | 响应式、暗黑模式、简体中文、角色权限 | Vben 既有能力 + Studio 自定义 |

| P2 | 自动优化广告投放表现、平台发布、真实支付 | 设计扩展字段，不在 Mock 伪装已实现 |
| P2 | Agent 托管模式、授权预算自动执行、自动 A/B 测试 | 仅展示“规划中”，不实现真实执行 |

### 2.1 为什么不做一键全自动作为第一版

一键生成可作为未来“托管模式”，但初期视频生成成本高、产品理解易偏、人物/品牌一致性难保障。**专业审核模式是默认**：用户确认每个**高成本边界**，不是每次文本输入都弹确认。

### 2.2 Mock 完成标准

- 不是静态原型；必须在浏览器中点通主要流程。
- Mock 运行需能演示**正常成功、失败、超时、取消、余额不足、版本冲突、重新进入恢复**。
- 前端 `services` 层不依赖 Mock 具体实现；未来切真实 API 不应重写页面。

## 3. 官方前端框架选型与开发环境

### 3.1 技术基线

- Vue Vben Admin **5.x**，选择 `apps/web-ele`（Element Plus 应用）。
- Vue 3 + TypeScript + Vite + Vue Router + Pinia。
- 使用 Vben 自带请求封装（基于 Axios），遵循其 V5 现有路由、权限、主题与国际化约定。
- CSS：沿用项目实际 Tailwind/变量体系；Studio 自定义 CSS 使用命名空间，禁止修改公共底层包来实现业务样式。
- 包管理：**pnpm**；先固定 tested commit/tag、`pnpm-lock.yaml` 和 `packageManager` 版本。
- Node.js：Vben 当前文档要求 **22.18.0 及以上**；推荐统一 Node 22 LTS，并以锁定版本实际要求为准。
- 测试：Vitest + Vue Test Utils；端到端建议 Playwright Test；如项目已有工具保持一致。
- Mock：优先复用 Vben `apps/backend-mock` 的 Nitro Mock 服务；后续替换 .NET 8 API。

> 官方文档：  
> - 仓库：https://github.com/vbenjs/vue-vben-admin  
> - 快速开始：https://doc.vben.pro/guide/introduction/quick-start.html  
> - Monorepo 结构：https://doc.vben.pro/guide/project/dir.html  
> - 服务端交互和 Mock：https://doc.vben.pro/guide/essentials/server.html

### 3.4 API Mock 切换约定

```env
# 示例值，字段名称按项目真实版本 request 配置适配
VITE_GLOB_API_URL=/api
VITE_NITRO_MOCK=true
VITE_APP_MOCK_BUSINESS=true
```

- `VITE_APP_MOCK_BUSINESS` 是**业务自定义开关**，不是 Vben 的官方内置变量，需要团队实现。
- 业务页只能调用 Repository / API Service（如 `projectApi.create()`），禁止页面直接导入 Mock JSON。
- Mock 和正式 API 必须保持同一请求、响应和状态枚举契约。
- 生产环境不依赖 Nitro 开发 Mock；上线前将业务 Mock 关掉并接真实服务。

### 4.3 角色与权限（Mock）

- `owner`：项目拥有者，管理项目、素材、创意、审批、消费与导出。
- `editor`：编辑者，可修改脚本和分镜、提交生成；实际扣费需要项目设置允许。
- `reviewer`：审核者，可评论、确认/拒绝镜头；默认不可扣费生成。

## 5. 贯穿全站的创作状态与门禁

### 5.1 项目阶段总览

建议 UI 展示 8 个步骤（第二、三阶段均明确区分产品理解和创意选择）：

| 阶段 | 中文名称 | 核心结果 | 需要确认 | 重新打开规则 |
|---|---|---|---|---|
| S1 | 产品资料 | URL、上传资料、演示授权摘要 | 是（资料已提交） | 可新增资料，旧理解版本可能过期 |
| S2 | 产品理解 | 产品画像、事实证据、用户痛点 | 是 | 修改上游内容提示下游受影响 |
| S3 | 创意方向 | 传播切口、3 套创意方向 | 是 | 重选创意需审查剧本/分镜 |
| S4 | 剧本规划 | 时长适配、故事节拍、完整剧本 | 是 | 改结构影响分镜时间线 |
| S5 | 图文分镜 | 每镜头文字、参考图与视觉设定 | 是 | 支持逐镜头审核与整体确认 |
| S6 | 动态预演 | 低成本整片节奏预览 | 建议是 | 允许返回分镜修改 |
| S7 | 镜头视频 | 分镜视频候选、版本、审核与计费 | 每个镜头 | 已确认镜头可解锁重新生成 |
| S8 | 最终合成 | 整片 MP4、渲染版本、导出 | 最终是 | 更换某镜头后整片变“待更新” |

### 5.2 顶部 Stepper 文案

`资料 → 理解产品 → 创意方向 → 剧本 → 图文分镜 → 低成本预演 → 镜头视频 → 完整成片`

显示状态：`未开始 / 进行中 / 待审核 / 已确认 / 发生变更需复核 / 已完成 / 失败`。不可进入后续步骤时，禁用操作并说明缺少哪个确认；已访问的上游页面允许返回。

### 5.3 审核与依赖规则

- 上游正式版本一旦变化，需计算后续**依赖影响范围**，而不是无条件清空所有结果。
- 若只是修改备注或错别字，允许不影响视频；修改产品事实、角色、创意、时长、旁白、参考图等应提示相关下游重新审核。
- 每次确认保存操作者、时间、版本 ID 和批注；用户能查看确认历史。
- “锁定”指正式引用不被后台异步任务覆盖；用户仍可主动编辑并创建新版本。
- 如果两个人先后确认同一镜头，必须出现版本冲突提示（Mock 可模拟 HTTP 409），不能悄悄覆盖。
- 用户退出后回来，自动恢复上次正在编辑的步骤和草稿；重要步骤切换前有未保存提示。

### 5.4 用户取消或关闭页面

- 已提交的生成任务继续按模拟任务规则完成；关闭浏览器不能当作成功取消。
- 停止生成只在任务允许的状态下生效（见计费章节）。
- 用户刷新页面后应恢复任务状态与余额，不可重复创建任务或重复冻结积分。

## 7. 页面详细设计（二）：资料输入与授权演示环境

### 7.1 S1 页面组成 `/studio/:id/ingest`

**页面结构**：上方 URL 栏和采集状态；左侧“资料来源”，中间“素材预览与采集明细”，右侧“AI 待分析清单/资料完整度”。

四种输入方式可组合，不互相排斥：

| 方式 | 用户输入 | 展示结果 | Mock 行为 |
|---|---|---|---|
| A. 公开 URL | URL、需要分析的页面范围 | 域名、页面标题、页面卡片、采集进度、模拟截图 | 切换 `PUBLIC_SUCCESS`、`PARTIAL`、`LOGIN_REQUIRED`、`FETCH_FAILED` |
| B. 授权登录 | 演示网址，演示账户授权方式 | 登录状态、探索页面树、测试账号标识（脱敏）、会话剩余时长 | 仅**模拟**浏览器授权流程，绝不实际发送账号密码 |
| C. 图片/录屏 | 截图、MP4/MOV/WebM 等本地素材 | 缩略图、视频预览、时间、文件体积、关联页面 | 本地 Blob 预览/模拟上传，生成素材 ID |
| D. 说明文档 | PDF/DOCX/TXT/Markdown/PPTX 等 | 文件列表、解析摘要（模拟）、页数/片段 | 模拟解析状态、证据引用与错误 |

**另补充**：品牌 Logo、主色、商标、可使用产品截图、已有广告/参考视频、允许对外展示的功能清单、禁止展示的信息等；这些不是必填，但建议显示“补充后效果更好”。

### 7.2 URL 抓取状态

- `NOT_STARTED`：未分析。
- `FETCHING`：正在模拟采集页面。
- `PUBLIC_SUCCESS`：获取公开营销页、功能页、FAQ 页等。
- `PARTIAL`：部分页面不可访问。
- `LOGIN_REQUIRED`：检测到登录门槛。
- `FETCH_FAILED`：无法访问、机器人限制或 URL 错误。

**状态反馈**：不应仅靠百分比；显示“发现首页 → 识别功能页 → 读取公开说明 → 生成摘要”的过程。所有进度为 **Mock 模拟**，勿让用户误认为已真正爬取外部网址。

### 7.3 登录演示系统的安全设计

推荐真实产品未来模式：**用户在隔离浏览器中自行登录** → 授权 Agent 使用当前演示会话 → 只读/限权探索 → 脱敏 → 会话到期撤销。作为备选，允许专门的低权限、模拟数据账号经服务端加密保险库存储，但从不把明文密码放进 LLM Prompt、浏览器缓存或前端日志。

**Mock 页面必须实现**：

1. “网站需要登录”提示 + “打开演示授权窗口”按钮。
2. 模拟授权对话框：`https://demo.example.test`、演示用户 `demo_viewer`；不要求填真实密码，若为了演示表单而允许输入，应**不保存、不回显、不写 console、不发往外域**。
3. 用户选择“模拟授权成功”后显示安全范围：仅白名单域名、只读操作、会话 30 分钟、演示数据、禁止删除/付款/外呼/客户数据导出等敏感操作。
4. 显示模拟探索路径（登录页 → 仪表板 → 功能 A → 功能 B），每页有截图和功能摘要。
5. 提供“撤销会话”“补充人工录屏”“跳过登录，以已有资料继续”操作。
6. `LOGIN_EXPIRED`、`MFA_REQUIRED`、`ACCESS_DENIED`、`NO_DEMO_DATA` 四种异常场景可切换演示。

**未来安全验收前置条件**：URL 白名单、阻断 localhost/内网/云元数据地址访问、限制跳转、沙盒执行、最小权限、敏感数据遮罩、会话清理、授权审计。**前端提示不等于服务端安全控制**。

### 7.4 上传文件交互

- 支持拖入、多选、逐文件进度、重试、取消、删除、预览、重命名、用途标签。
- 示意限制（可配置）：单图片 ≤20MB、单视频 ≤500MB、单文档 ≤50MB、每项目 ≤100 个素材；为**前端暂定交互限制**，后端上线时统一调整。
- 图片支持 JPG/PNG/WebP；录屏支持 MP4/WebM/MOV（浏览器原生不支持时展示无法预览提示）；文档 PDF/DOCX/TXT/MD/PPTX。若支持 DOC 旧格式，文档解析能力需后端单独确认，当前只做 Mock。
- 发现同名文件时不直接覆盖；创建新素材记录。
- 预览前校验文件类型，预防 SVG/HTML 主动脚本、恶意 URL。不要把用户文件上传到外部公共图床。
- 本地 `blob:` URL 只在当前浏览器会话有效，刷新后若 Mock 不能还原真实媒体，请显示“本地素材需重新选择”，不得显示破损播放器。
- 上传失败、格式不支持、文件过大、重复文件、素材无权使用，都要有明确提示。

### 7.5 资料覆盖度面板

建议展示：公开产品信息、核心功能、品牌、目标受众、真实产品画面、真实用户反馈、成功案例、使用前后对比、宣传禁区。标记 `已确认 / 待验证 / 缺失`，不要仅给一个不透明百分比分数。

**确认动作**：“资料已准备好，开始产品分析”。此按钮会生成产品资料快照 `ingestionSnapshotId`。

## 8. 页面详细设计（三）：产品理解与用户痛点

### 8.1 S2 `/studio/:id/understanding`

页面建议采用 **左侧证据来源 → 中间 AI 分析报告 → 右侧人工修正/确认**，报告支持折叠分组和可编辑字段。

**分析报告必须展示**：

1. 产品是什么（一句话定位、产品类别）。
2. 目标用户画像：谁会使用、使用场景、购买决策者/使用者区别。
3. 核心功能清单：名称、说明、用户可见效果、真实证据。
4. 与传统做法相比的差异：旧方案、新方案、为何值得关注。
5. 真实用户潜在痛点（不少于 5 个候选）：场景、情绪、损失/麻烦、产品如何解决。
6. 创新体验/身份价值/最终结果/情绪愿景等候选价值。
7. 品牌信息与风格：Logo、主色、定位、禁止使用的口径。
8. 可使用的证据及缺失信息：来源页面、录屏时间戳、文档页码、人工提供的陈述。
9. 风险与不确定性：是否仅从网站文案推测、是否需要用户确认、是否禁止营销声称。
10. 适合宣传的产品功能与不适合拍摄的敏感部分。

**单条洞察数据示例**：

```json
{
  "id": "pain-knowledge-001",
  "persona": "经常收藏技术文章的开发者",
  "scenario": "收藏了大量文章后，真正要使用时找不到",
  "painPoint": "收藏并不等于掌握或可检索",
  "emotion": ["焦虑", "挫败"],
  "linkedFeatureIds": ["feature-semantic-search"],
  "evidenceIds": ["evidence-site-feature-page"],
  "evidenceLevel": "hypothesis",
  "reviewStatus": "pending",
  "editorNote": "待确认是否有真实访谈证据"
}
```

`evidenceLevel` 建议定义：

- `verified`：经已提供产品资料或明确事实验证。
- `user_confirmed`：由产品拥有者确认，尚不代表外部市场验证。
- `hypothesis`：AI 合理推断，需确认。
- `unsupported`：缺少依据，不允许用作确定性广告主张。

**用户可操作**：

- 修改产品定位、用户画像、功能、痛点描述；增加/删除痛点。
- 标记“功能不支持”“痛点不真实”“禁止这样宣传”。
- 点击证据查看具体截图/文档摘录/录屏时段（Mock 展示来源）。
- 选择“让 AI 深挖此痛点”“重新分析指定功能”“补充资料再分析”。
- 提交确认后生成 `productUnderstandingRevisionId`。

**特殊情况**：产品采集不全时不能以确定语气展示“全功能已理解”；页面必须支持“先以现有资料继续，但后续创意标记为待验证”。

## 9. 页面详细设计（四）：价值切口发现与创意方案

### 9.1 本产品核心概念：价值切口 ≠ 表现方式

**价值切口**（故事为什么有意义）：产品解决什么问题、创造了什么新体验、带来怎样的结果或身份变化。  
**表现手法**（如何讲得吸引人）：悬念、幽默、反转、夸张、3D 视觉奇观、情绪、动态排版等。

不要将“幽默”与“用户痛点”视为同一维度，也不要机械规定每款产品只能属于一个类型。

### 9.2 创意切入角度库（必须在 UI 配置化）

| 编码 | 类型 | 触发的观众反应 | 例子 | 主要维度 |
|---|---|---|---|---|
| `UNCONVENTIONAL` | 反常规/认知刷新 | “原来还能这样？” | PDF/Word 简历 → 3D 网页 | 价值 |
| `PAIN_EMPATHY` | 真实痛点/情绪共鸣 | “这不就是我？” | 收藏一堆文章却找不到 | 价值 |
| `BEFORE_AFTER` | 结果蜕变/前后反差 | “变化竟然这么大” | 混乱任务 → 清晰协作 | 价值+表达 |
| `IDENTITY` | 身份认同/自我表达 | “这是我想成为的样子” | 个性化数字名片/简历 | 价值 |
| `MYSTERY` | 悬念揭秘/好奇心 | “接下来会怎样？” | 一个网址能做成什么视频？ | 表达 |
| `BENEFIT` | 极致收益/效率价值 | “原来能省这么多麻烦” | 自动化报表减少重复工作 | 价值 |
| `ASPIRATION` | 梦想愿景/新可能 | “我也想拥有这个” | 一个人拥有数字工作室 | 价值 |
| `PROOF` | 真实案例/信任证明 | “这是真的有效吗？” | 可核实的真实客户案例 | 价值+证明 |
| `LIVE_WOW` | 现场惊艳/眼见为实 | “太有意思了” | 图片即时变 3D 可互动形象 | 表达+产品演示 |
| `HUMOR` | 幽默娱乐/主动传播 | “好笑，值得转发” | AI 员工在电脑里争工作 | 表达 |

**组合机制**：例如 3D 简历 = 主切口 `UNCONVENTIONAL` + 辅切口 `IDENTITY` + 表现手法 `LIVE_WOW`；知识库 = 主切口 `PAIN_EMPATHY` + 表现手法 `HUMOR` 或 `BEFORE_AFTER`。

### 9.3 S3 `/studio/:id/angles` 页面

默认并排/轮播展示 3 套**显著不同**的候选创意：

- A：反常规/认知刷新（如果产品本身具有真实的新表达）。
- B：真实痛点/情绪共鸣。
- C：视觉隐喻/现场惊艳/悬念/幽默（按产品决定，不强制每次相同）。

每套卡片必须包含：

- 创意命名；一句话故事；主/辅传播切口与适配理由。
- 目标用户；具体场景；观众开头 3 秒的心理钩子。
- 开场话术（中文）、主要剧情冲突、反转、高潮、产品自然出现时刻、CTA。
- 推荐视觉风格：卡通 3D、写实、动态拼贴、MG 等；代表参考图 1～3 张（Mock 资源）。
- 是否支持产品真实功能的证据标记、风险提示。
- 创意评分维度（内部启发式而非绝对数值）：相关性、可理解性、新颖性、视觉表达性、真实性、潜在转化动机。
- 是否需要新素材及生成成本级别（低/中/高，估算）。

**操作**：选择某套、修改文案、增加方向要求、“让 AI 再来三套”、收藏备用、对比两个方案、锁定选定方案、返回补资料、添加不允许出现的表述。

**拒绝‘三套一样’的验收要求**：不同候选在人物/场景/情绪冲突/叙事结构/主切口中至少有 2 项本质差异；不能仅换标题、配色、词序。

### 9.4 3D 简历示例数据（贯穿全站）

| 方案 | 传播切口 | 视频开场 | 价值体现 |
|---|---|---|---|
| A：让简历活过来 | PDF → 3D 网页，认知刷新 | “2026 年，你还在发 PDF 简历？” | 简历不再只是静态文字，变成可交互展示 |
| B：为什么没人记住我 | 传统简历缺乏个性表达 | 一堆长得一模一样的简历 | 展示作品、技能与独特个人形象 |
| C：把自己装进网页 | 视觉奇观/身份表达 | 卡通数字人从简历纸里跳出来 | 不走寻常路的个人品牌形象 |

> 这些均为**创意假设示例**；不应声称 3D 简历必然提高求职通过率或招聘成功率。

### 9.5 创意选择的决策门槛

若产品缺乏足够独特切入点，显示：“当前资料缺少支撑强创意的明显差异，建议补充实际用户故事、真实效果或独特功能”。允许用户“仍继续”，但提示创意可能较弱。不能虚构强差异化。

## 10. 页面详细设计（五）：目标时长适配与完整剧本

### 10.1 为什么必须先确认时长，再写完整剧本

**创意概念**与**完整剧本**是不同数据：概念可以适用于多种时长；完整剧本必须根据内容容量和节奏设计。前端须分开存储 `creativeConcept` 与 `scriptRevision`。

### 10.2 S4 `/studio/:id/script` 页面布局

- 左侧：选中的创意核心、目标用户、主传播切口。
- 中间：时长适配建议、故事节拍时间线、完整中文剧本（结构化段落）。
- 右侧：AI 导演对话、剧本修改记录与风险提醒。
- 顶栏：目标视频规格（时长、画幅、平台、语言、风格）、版本切换、保存草稿、重新生成、确认剧本。

### 10.3 视频时长可选项

- 15/30/45 秒：高密度传播与短视频广告。
- 60 秒：常规产品营销故事。
- 90/120 秒：品牌故事、多章节叙事及深度版本。
- 可预留自定义时长（初期建议 15～180 秒范围；无实际模型能力限制，合成时长由业务规则控制）。
- 画幅 `9:16` / `16:9` / `1:1`；不同画幅可有不同构图和镜头要求。

### 10.4 “创意适合 30 秒，客户要求 120 秒”的专门交互

页面必须出现解释型提示，而不是自动填充空镜头：

> 当前创意最适合约 **30 秒**，但目标是 **120 秒**。为了维持叙事吸引力，请选择：
>
> **A｜完整故事扩写**：加入人物动机、背景、冲突、转折、价值证明等新故事节拍；  
> **B｜120 秒多章节影片**：多个互相关联的创意章节，分别从不同角度讲同一个产品；  
> **C｜保留 30 秒版本**：不为了凑时长降低质量，另可衍生多条独立短视频。

如果用户坚持 120 秒但证据和情节容量不足，提示补充素材或确认接受可能的节奏风险，不得编造成功案例、损失数字、用户评价。

**交互状态**：`SUFFICIENT / CAN_EXPAND / NEEDS_NEW_CHAPTERS / NOT_RECOMMENDED`。选择策略后重新生成**完整剧本**，不是把 30 秒已有镜头机械变速。

### 10.5 示例：120 秒“3D 简历”七个故事节拍

| 节拍时间 | 叙事作用 | 内容 |
|---|---|---|
| 0–10s | 强钩子 | 面试官面前堆满相似 PDF 简历 |
| 10–30s | 建立冲突 | 创作者怎么调整排版都无法展示自己 |
| 30–50s | 认知转折 | 为什么简历必须是静态文件？ |
| 50–75s | 视觉高潮 | 纸张破碎，3D 人物与数字空间出现 |
| 75–95s | 价值深化 | 项目、技能、经历在个人空间中呈现 |
| 95–110s | 真实落地 | 真实产品的网页形式自然露出 |
| 110–120s | 情绪收束/CTA | “下一次介绍自己，发一条链接就够了。” |

**注意**：上表 7 段是故事节拍，不等于只有 7 个视频镜头。一个节拍可包含 2～4 个镜头，最终可能 15～25 个镜头。

### 10.6 时长分配校验

- 全片目标时长在脚本阶段以故事节拍时长加总为准。
- 后期镜头转场可能占用/重叠时间，必须在时间线计算净时长：`finalDuration = sum(shotDuration) - sum(overlappingTransitionDuration) + insertedStandaloneDuration`。
- 不以“100% 必须刚好120秒”强迫填充；允许配置 ±2 秒创作容差，最终渲染前明确显示是否符合用户交付规格。
- 每个故事节拍必须说明新增信息/情绪/剧情价值；无价值的重复节拍标记为低质量。

### 10.7 结构化剧本编辑器

支持增删节拍、拖拽排序、编辑片段标题/叙事目标/冲突/反转/旁白/预计时长/产品关联功能、时间分配可视化，自动记录修订版和差异。确认剧本后才能批量生成分镜图片。

## 11. 页面详细设计（六）：图文分镜工作台（最重要页面）

### 11.1 核心交互目标

用户能在**没有任何昂贵视频生成**的情况下，看清整条广告将讲什么、每个镜头大概长什么样、台词说什么、在哪里出现品牌、时长是否合理。

页面不能简单堆表格，应有“图文分镜卡片 + 视频画面预览 + AI 导演聊天 + 底部故事时间线”。

### 11.2 布局草图（宽屏）

```text
┌ 返回项目 │ 项目名称 │ 步骤 5 / 8 │ V3 已保存 │ 模拟余额 │ 用户 ───────┐
│ 资料 ✓  理解 ✓  创意 ✓  剧本 ✓  [图文分镜] 预演  镜头视频  完整成片     │
├────────────────┬─────────────────────────────────┬────────────────────┤
│ 分镜列表        │       当前选中分镜大图            │ AI 创意导演         │
│ [01 5s ✓]      │  ┌──────────────────────────┐   │ 对话记录           │
│ [02 8s ✓]      │  │       参考图片 9:16       │   │ 修改建议           │
│ [03 8s 待审]   │  └──────────────────────────┘   │ 用户反馈输入框     │
│ [04 6s ...]    │  剧情 | 动作 | 运镜 | 台词 | 字幕  │ [生成修改方案]     │
│ ...            │  转场 | 音效 | 来源 | 风险       │                     │
│ [新增镜头]     │ [保存] [重生图片] [确认镜头]     │                     │
├────────────────┴─────────────────────────────────┴────────────────────┤
│ 故事时间线 / 镜头缩略图 / 时长块 / 总时长 120s  [预演] [确认整组]    │
```

在 1366px 及以下可折叠右侧 AI 面板；平板可把镜头列表做可展开抽屉；移动端应能审核与评论，但可限制复杂时间线拖拽，明确提示推荐桌面编辑。

### 11.3 每个分镜卡必须展示的字段

| 字段 | 说明 |
|---|---|
| 镜头编号及 `shotId` | 01、02 等；拖拽排序不改变永久 ID |
| `storyBeatId` | 归属哪个故事节拍 |
| `startTime` / `duration` | 在全片的排布和播放时长 |
| `title` / `narrativePurpose` | 镜头标题、叙事目的（钩子/冲突/反转/价值/CTA） |
| `referenceImageIds` | 一张或多张分镜参考图（含版本） |
| `shotDescription` | 场景与画面详细描述 |
| `characterIds` / `sceneIds` | 使用哪些角色/背景/道具 |
| `actionDescription` | 人物动作和事件变化 |
| `cameraMotion` | 景别、推拉摇移、快慢及角度 |
| `visualStyle` | 3D 卡通、写实、MG、拼贴、动态文字等 |
| `narration` | 中文旁白、说话人、情绪、语速 |
| `subtitles` | 字幕文案与显示时机 |
| `musicCue` / `sfx` | 背景音乐/音效/节奏标记 |
| `transitionIn/Out` | 与相邻镜头的衔接设计 |
| `productPlacement` | 产品以什么方式自然出现 |
| `evidenceIds` | 支撑广告主张的产品来源证据 |
| `generationMode` | `ai_video` / `motion_graphics` / `real_footage` / `image_animation` |
| `status` / `revision` | 待审/已确认/需复核/错误、分镜修订版本 |
| `estimatedCredits` | 预计后续镜头视频生成成本（仅估算） |

### 11.4 分镜卡操作

- 编辑：对文字、台词、人物、镜头语言、时长逐项修改。
- AI 修改：用户用自然语言描述问题，AI 给出**修改计划与影响范围**，确认后才改动对应版本。
- 重新生成**参考图片**：先询问是否仅重生图片（可能消耗图片积分），避免误触视频生成费。
- 增加/删除/复制/拆分/合并镜头；变更镜头顺序；拖动调整时长。
- 逐镜头“确认”与“退回修改”；整组“全部确认”前要检查未确认镜头、证据风险、时长约束。
- 图文分镜修订历史、图片版本选择、参考图固定/锁定。
- 标记“该镜头使用的品牌 Logo 必须真实”“画面中的网站文字必须真实”，避免视频模型出现错误文字。
- 自动保存草稿与手动明确确认区分，不能“保存草稿”等于“审核通过”。

### 11.5 角色一致性和视觉风格圣经（Visual Bible）

在工作台提供“全片视觉规范”抽屉：

- 主角清单：人物名称、外貌、发型、服饰、性格、参考图、禁止变化项。
- 场景清单：地点、光线、色温、背景关键物、镜头连贯关系。
- 视觉语言：3D 卡通/电影感/动态贴纸/大字排版/转场风格。
- 品牌：Logo、主色、禁用元素、字体、真实产品页面引用。
- 音频：旁白风格、语言、语速、情绪、背景音乐风格、音效原则。
- 输出：分辨率、画幅、帧率、字幕安全区。

如果修改全局人物设定，弹窗说明影响镜头：如“关联镜头 03/04/08/11 需要复核，已有确认视频不会自动覆盖”。

### 11.6 用户看图审剧本时的关键体验

分镜生成结果必须是**图片 + 对应剧本**联动；点击某张图就高亮对应旁白、时间轴段落和角色设定。图片是视频生成的参考输入之一，而不是仅做装饰；需要记录实际生成镜头时使用的图片版本。

### 11.7 局部修改的语义分类

| 用户说的话 | 识别类型 | 系统计划 | 费用影响 |
|---|---|---|---|
| “文字改成更幽默” | `SCRIPT_TEXT` | 更新脚本和字幕 | 不涉及视频生成费用 |
| “纸张先炸开再出人物” | `MOTION_ACTION` | 更新动作与镜头提示词 | 生成前再次报价 |
| “人物表情夸张些” | `CHARACTER_EXPRESSION` | 保持角色图，修改表情提示词 | 可能重生成镜头 |
| “主人公换成机器人” | `GLOBAL_CHARACTER` | 新角色设定，标记相关镜头受影响 | 可能涉及多个镜头费用 |
| “这句旁白不满意” | `NARRATION_AUDIO` | 改旁白/字幕/音频轨 | 可不重生成视频画面 |
| “镜头延长 5 秒” | `TIMELINE` | 调整时长，必要时镜头扩展 | 重新估价并重算全片时长 |
| “画面从横版改竖版” | `ASPECT_RATIO` | 修改构图、所有依赖镜头待检查 | 可能全局大变更 |
| “把这段删掉” | `STRUCTURE` | 删除镜头、更新剧本节拍 | 可能影响过渡和旁白 |

**AI 不能承诺每个模型都能精确修改视频局部像素**；对于不支持原视频编辑的模型，应提示“将基于参考素材重新生成候选片段”。

## 12. 页面详细设计（七）：低成本整片预演（Animatic）

### 12.1 目的

在正式视频模型投入前，用**分镜图片 + 镜头时长 + 旁白/临时音效 + 基础推拉/淡入淡出**构成粗剪预览，让用户判断整体故事是否顺、节奏是否合理。

### 12.2 S6 `/studio/:id/animatic` 页面

- 中央 9:16 或 16:9 播放器；底部简化时间线；右边可定位镜头/反馈。
- 播放/暂停、跳转镜头、按段落循环、切换字幕、设置静音。
- 允许替换分镜图片、调旁白速度、调整镜头时长、标记“太拖沓/太平淡/看不懂”。
- 页尾提供“确认预演，准备生成视频”，确认后创建 `animaticRevisionId`。
- Mock 方案：浏览器定时切换图片 + CSS 动画 + Web Audio 或静态音频素材；若无 TTS，则至少**字幕/时间线同步运行**，不得伪称生成了真实配音。

### 12.3 预演与最终视频的区别

- 预演可在不调用视频模型的前提下确认故事和节奏。
- 预演不是实际生成结果，需有“低成本预览 · 画质非最终效果”标签。
- 修改预演底层剧本/时长会使相关分镜确认状态待复核。

## 13. 页面详细设计（八）：单镜头视频生成与审核

### 13.1 S7 `/studio/:id/generate` 主界面

每个镜头至少有：参考图片、分镜文字、已批准视频缩略图、当前候选视频、任务状态、生成版本数、费用累计、操作入口。

页面分左右或双播放器布局：

```text
┌ 镜头07 · 00:38–00:46 · 8秒 │ 正式 V1 ✓ │ 待审候选 V3 │ 费用明细 ┐
│ [旧版 V1 播放器]                       [候选 V3 播放器]               │
│ [同步播放] [逐帧/循环] [对比模式]  [字幕开关] [查看分镜输入版本]         │
│                                                                     │
│ AI 修改意见：人物出场普通，希望纸张先破碎，人物再跳出 ...             │
│ AI 修改计划：只改动作与运镜，锁定人物形象 / 旁白 / 8秒时长             │
│ [查看修改差异] [修改分镜] [重新生成并报价]                             │
│                                                                     │
│ 历史：V1 已批准 | V2 已拒绝 | V3 待审核                                │
│ [采用 V3] [继续修改] [拒绝 V3] [回退 V1]                               │
└─────────────────────────────────────────────────────────────────────┘
```

**注意**：真实视频播放器在 Mock 可以使用示例 MP4 或本地示例素材；不能用图片冒充“视频生成成功”。如果没有视频示例，明确显示“模拟生成成功，当前无可播放示例片段”。

### 13.2 单镜头版本模型（三层版本）

1. `shotRevision`：图文分镜文本、参考图、角色、旁白的**不可变修订快照**。
2. `shotVideoVersion`：每次真正生成的视频文件及其输入快照、模型参数、生成任务，版本 V1/V2/V3；是**候选**。
3. `activeApprovedVersionId`：时间线当前正式采用的视频版本指针；只有明确人工采用才发生变更。

另有 `projectRenderVersion`：整片合成的不可变时间线快照与最终 MP4 记录。

### 13.3 创建候选版的基本规则

- 无论重生多少次，旧视频文件与原版本记录始终存在。
- “生成任务成功”≠“用户审核通过”≠“整片使用新版”；三者状态分离。
- 新候选版本成功后进入 `PENDING_REVIEW`，不会自动更新 `activeApprovedVersionId`。
- 已确认版本可解锁编辑，先创建新修订，原正式引用继续有效直到采用新版。
- 版本编号建议镜头内部递增，**不要用数组下标、也不要通过时间戳猜测版本**。
- 与正式版本关联的脚本/参考图是不可变快照，UI 能追溯“哪个版本用了哪张图/哪段文案/哪组模型参数”。
- 若多个生成任务并发完成，分别创建自己的候选；不能因最后返回就自动覆盖正式版本。

### 13.4 候选审核状态

`PENDING_REVIEW` → `APPROVED`（被采用）或 `REJECTED`（被拒绝），可能存在 `SUPERSEDED`（旧正式版本被新正式版本取代）、`ARCHIVED`（隐藏但可查）。状态属于视频版本，不属于视频生成任务。

**采用新版时**：版本检查（乐观锁 `expectedShotRevision`）→ 确认采用 → 更新正式指针 → 记录操作 → 使整片 `OUTDATED` → 提示重新合成。

**回退旧版**：选历史版 → “采用此版本” → 重新设置正式指针 → 无需视频模型调用、无需再次扣视频生成积分 → 整片待重新合成。

### 13.5 版本对比能力

- 左右同步播放，支持“同步跳转起点”“单独循环当前镜头”。
- 元数据差异：剧本修订、提示词摘要、参考图、模型、时长、分辨率、种子（如果存在）、生成费用、AI 修改意图、创建时间。
- 展示 V1/V2/V3 及其审核状态；时间线只使用“已采用”版本。
- 可选“新增候选数量 1～N”，候选数增加时需显式显示成本增加。
- 如果新视频时长与剧本不匹配，进入待修复状态，禁止直接作为合格整片素材。

### 13.6 生成费用确认弹窗（必须完整交互）

必须展示：

1. 镜头名称与 ID、当前剧本/参考图版本。
2. 视频模型（如“示例模型 A/B”；真实模型名称以后配置化，不要在 Mock 里承诺具体供应商能力）。
3. 目标秒数、分辨率、画面比例、是否带音频、候选数量。
4. 输入素材与预计生成方式（图生视频、视频延展、程序化动画等）。
5. 本次报价（积分）、模拟钱包可用余额、冻结后余额。
6. 报价有效期限、允许的自动重试次数、收费规则。
7. “仅生成当前镜头，不会覆盖旧视频”；提示“生成成功但主观不满意，重新生成需再次确认费用”。
8. “确认冻结并创建任务”“返回调整”按钮。

**重点**：动态改变时长/模型/候选数量时必须重新报价；确认任务时校验报价使用的输入快照是否已变化。

### 13.7 任务进度与完成通知

- 任务状态：队列中、提交供应商、生成中、下载校验、完成、失败、取消、结果待核对。
- 显示模拟排队位置/阶段、任务编号、已耗时（可用真实前端计时显示）、能否取消。
- UI 进度需要明确“模拟估算”，不能宣称可精确反映模型内部进度。
- 完成后弹消息/任务中心徽标提示，点击可定位待审候选。
- 失败时展示可理解原因，提供“查看费用释放情况”“重试创建新任务（如需收费）”。

### 13.8 单镜头输出模式（不要全交给视频大模型）

| 模式 | 场景 | 前端操作 |
|---|---|---|
| `AI_VIDEO` | 人物动作、叙事镜头、视觉奇观 | 支持模型、秒数、参考图、候选版本 |
| `VIDEO_EXTENSION` | 已有视频动作继续，或尾帧续接 | 显示上一个片段/尾帧及连续性风险 |
| `IMAGE_ANIMATION` | 静态图轻微推拉/视差 | 配置基础动效，低成本 |
| `MOTION_GRAPHICS` | 大字排版、Logo、网页动效、贴纸 | 使用程序化动画，文字/品牌更准确 |
| `REAL_FOOTAGE` | 用户授权产品录屏、真实操作片段 | 剪裁/标记敏感信息/展示来源 |

**模型能力不应写死**：不同供应商可能只支持固定秒数、首帧/尾帧、原片编辑、音频或延展等部分能力。业务 UI 根据模型能力元数据动态禁用选项并说明原因。

## 14. 页面详细设计（九）：最终合成、审核与导出

### 14.1 S8 `/studio/:id/render`

**进入门槛**：所有参与最终成片的视频镜头必须有 `activeApprovedVersionId`，其他程序化动画/录屏镜头必须有已确认素材或可执行的渲染配置。

展示：

- 全片镜头列表及已选正式版本。
- 画幅、目标时长、实际计算净时长、清晰度、帧率、字幕/配音/音乐轨。
- 转场、音量归一、字幕安全区、视频格式与码率设置。
- 检查项：镜头是否完整、角色和风格是否一致、品牌 Logo 是否正确、字幕与配音是否冲突、CTA 是否可见。
- “合成视频”按钮 → 创建 Mock 合成任务 → 进度 → 完整预览播放器。
- 历史成片版本 V1/V2/… 与其所用所有镜头版本清单（时间线快照）。

### 14.2 FFmpeg 正式合成工作流（仅作未来接口契约）

1. 每镜头素材验证（可用/已确认、时长、编码、分辨率、帧率、音轨）。
2. 合成服务按时间线统一格式、镜头缩放、字幕、音效、背景音乐、转场。
3. 对齐旁白与字幕，处理转场叠化引起的净时长变化。
4. 输出 MP4（建议 H.264 + AAC 的常见兼容配置），生成封面、时长、文件大小、校验结果。
5. 用户预览并反馈；如果只有镜头 07 需要改，先在 S7 重生/采用，再重新渲染 S8；旧整片 V1 保留。

**前端不负责 FFmpeg 真正执行**，只负责任务参数、进度、预览、失败恢复与结果展示。开发阶段 Mock 伪造“已生成结果记录”时必须标识为演示数据。

### 14.3 整片审美与叙事质量（不同于技术合成成功）

技术上 MP4 可播放，不代表广告好看。页面提供两个质检区域：

- **自动检查（Mock）**：素材缺失、画幅错误、时长异常、字幕超出安全区、相邻镜头冲突、Logo 缺失、音轨问题。
- **创意体验审核**：故事连贯、开头 3 秒吸引力、角色一致、情绪节奏、产品切口是否清晰、品牌植入是否自然、是否像教程、是否存在不实广告主张。

必须显示“AI 评价为辅助建议，需人工审核”，不能以主观分数保证传播效果。

### 14.4 导出与交付

- 输出规格：竖版 9:16、横版 16:9、方版 1:1（如版本具备不同素材）；分辨率选择示意 720p/1080p，真实能力以后根据模型与合成服务决定。
- 导出目标：抖音/视频号/B站/TikTok/官网/销售演示；提示不同平台可能需调整字幕安全区及营销口径。
- 可下载内容（未来）：MP4、封面、SRT 字幕、文案、图文分镜 PDF、素材清单；**本期至少 Mock 展示导出项**，可用小型示例文件供下载，但不得假装 AI 成片已真实生成。
- 成片版本与镜头来源版本永久可查；删除项目时必须提示历史费用/审计的保留政策。

## 15. 单镜头重新生成：前端需要实现的完整版本状态机

### 15.1 三个对象的状态严格分离

**生成任务 `GenerationJob.status`**：

```text
CREATED -> QUEUED -> SUBMITTED -> RUNNING -> DOWNLOADING -> SUCCEEDED
                        |             |             |
                        +-------------+-------------+-> FAILED
                                    |
                                    +-> RECONCILING -> SUCCEEDED / FAILED
CREATED / QUEUED -> CANCELLED（可撤销时）
SUBMITTED / RUNNING -> CANCELLING -> CANCELLED / RECONCILING / SUCCEEDED
```

- `CREATED`：创建任务，冻结积分、生成订单号。
- `QUEUED`：模拟等待队列。
- `SUBMITTED`：已向供应商提交；未来须记录 `providerTaskId`。
- `RUNNING`：供应商处理。
- `DOWNLOADING`：下载结果、检查视频、上传 MinIO。
- `SUCCEEDED`：视频文件已产生并验收，创建待审核候选版本。
- `FAILED`：明确失败，遵循账务规则释放冻结额度。
- `RECONCILING`：结果不确定，查询供应商，**不应盲目重复调用或扣费**。
- `CANCELLING`/`CANCELLED`：取消请求与确认取消区分；提交供应商后的退款取决于真实规则。

**候选视频 `ShotVideoVersion.reviewStatus`**：

`PENDING_REVIEW`、`APPROVED`、`REJECTED`、`SUPERSEDED`、`ARCHIVED`。

**项目最终成片 `ProjectRender.status`**：

`NOT_READY`、`READY`、`QUEUED`、`RENDERING`、`COMPLETED`、`FAILED`、`OUTDATED`。

### 15.2 审核事件必须具备乐观锁

用户采用 V3 前提交 `expectedActiveVersionId` 和 `expectedShotVersionNo`。如果后台已有更新，Mock 返回 409，前端展示：

> 该镜头已被其他操作更新。请刷新比较最新正式版本与您当前准备采用的候选。

可选操作：“刷新详情” / “查看差异” / “取消采用”。不可静默覆盖他人选择。

### 15.3 镜头依赖变化与版本传播

| 上游变化 | 对现有视频版本的处理 | 对下游的处理 |
|---|---|---|
| 修改镜头标题或管理备注 | 保留，通常不需重生 | 不标记整片过期 |
| 修改旁白文案 | 原视频不覆盖 | 标记该镜头音频/字幕轨待更新；视画面是否需同步决定 |
| 修改单镜头动作 | 旧版保留，新建输入修订 | 建议生成新候选；相关转场待审 |
| 修改主角外形 | 旧版保留 | 找出所有引用该角色的镜头并提示复核 |
| 修改时间线顺序/时长 | 旧视频保留 | 时间线快照过期，最终合成待更新 |
| 修改全片画面比例 | 旧版保留 | 相关镜头构图/字幕/合成规格待复核 |
| 修改产品事实/宣传限制 | 旧版保留 | 标记所有涉及该事实的镜头为风险待复核 |

### 15.4 版本树的视觉呈现

“V1 正式 → V2 被拒绝 → V3 待审核”是同一个镜头不同生成结果的历史；如果 V3 是基于 V1 的新修订生成，需以 `parentVersionId` 记录来源，不要假定所有版本都是线性的。

本期可以先使用版本列表 + 修改差异弹窗；未来再扩展版本树视图。

## 16. 积分报价、冻结、扣费、退款与账单

### 16.1 先确定商业行为，不要只画积分数字

建议采用**一次成功交付候选视频即计费**，与是否被用户最终采用无关；用户对主观效果不满意后再次生成，属于新生成订单，需要再次确认新报价。

但具体费用以未来模型 API、套餐及用户协议为准。本阶段只能提供**明确标注的模拟规则**，不能接真实支付。

### 16.2 交互流程

```text
用户请求生成/重生
    ↓
AI 确定修改范围、输入修订号
    ↓
报价 API → [单价档位、时长、候选数、价格、有效期、报价上限]
    ↓
用户核对、选择模型、确认
    ↓
事务性预冻结（Mock 模拟） + 创建订单 + 生成任务
    ↓
等待结果
    ├─ 成功交付候选 → CAPTURE / 完成结算
    ├─ 明确失败 → RELEASE / 恢复可用余额
    ├─ 模型已受理但超时 → RECONCILING / 先冻结待核查
    └─ 取消 → 依据是否已受理与明确规则结算/释放
```

### 16.3 默认模拟价格（仅 Mock，非供应商报价）

| 档位 | 示例积分单价 | 用途 |
|---|---:|---|
| `standard` | 3 积分 / 秒 / 候选 | 测试标准档 |
| `premium` | 6 积分 / 秒 / 候选 | 测试高质量档 |
| `motion_graphics` | 可设 0 视频生成积分 | 不调用 AI 视频模型；渲染费另行配置 |
| 图片重生 | 例如 2 积分 / 张 | 测试小额独立图片费用 |
| 文本 AI 调整 | 初期演示 0 视频积分 | 后续可接通用 AI 文本额度 |

**示例**：8 秒 × 3 积分/秒 × 1 候选 = 24 积分；2 候选 = 48 积分。模型实际时长如果只支持 5/10/15 秒档位，报价应按实际将被调用的档位或供应商计费规则计算，不能简单线性估算。

### 16.4 模拟钱包

初始 `availableCredits=120`、`heldCredits=0`。

- 下单冻结 24：可用 96，冻结 24。
- 成功并完成结算：可用 96，冻结 0，累计消耗 24。
- 若明确失败：释放 24，可用 120，冻结 0，累计消耗 0。
- 若已提交后取消但供应商结果未确认：继续显示“等待费用核对”，不能直接承诺返还。

**所有积分动作**必须通过独立 `billingService` 模拟处理，不可从 UI 组件直接 `wallet.balance -= n`。

### 16.5 账务订单状态

- `QUOTED`（已报价）
- `HELD`（冻结中）
- `CAPTURED`（已正式结算）
- `RELEASED`（已释放）
- `PARTIALLY_CAPTURED`（部分候选成功，部分额度释放）
- `RECONCILING`（供应商费用核对中）
- `EXPIRED`（报价过期）

### 16.6 账务流水动作

`HOLD` / `CAPTURE` / `RELEASE` / `ADJUSTMENT` / `TOPUP_DEMO`。

**业务约束**：

- 每个订单的冻结、结算、释放动作具备唯一事务 ID。
- 同一笔订单最多结算一次；回调重复不得二次扣费。
- 报价需记录 `inputRevisionHash`，输入变化后旧报价失效。
- 报价应为经用户明确确认的**最大收费额度**；自动重试超出预算，必须重新申请授权，不得自动追加扣费。
- 历史版本查看、已生成视频回退、用户采用候选，原则上不重复收费。
- FFmpeg 重新合成是否单独收费属于未来套餐规则，本期默认包含一定的模拟免费次数，不隐藏费用。
- 用户角色不具备付费权限时显示“请联系项目拥有者”而不是暗中生成。

### 16.7 必备账单页面 `/billing`

**积分卡**：总积分、可用积分、冻结积分、已消费积分、最近结算、模拟充值入口。  
**账单列表**：日期、项目、镜头、候选版本、任务 ID、计费动作、积分变更、余额变化、状态、模型/秒数、订单详情。  
**明细弹窗**：报价快照、授权确认时间、供应商模拟任务、幂等键、失败/释放原因。  
**演示充值**：标记“仅用于前端测试，无真实支付”；可以一键增加 100/500 模拟积分，以验证余额不足恢复流程。

### 16.8 费用异常交互

- 余额不足：生成按钮灰态或点击提示差额，支持调整模型/时长/候选数或 Mock 充值。
- 费用报价过期：不可继续，重新获取报价。
- 输入修订已变化：报价失效，解释“分镜已修改，需要重新报价”。
- 已冻结但任务提交失败：显示等待恢复/释放，并提供账务明细。
- 已成功交付但用户拒绝候选：明确说明本次视频生成额度已结算。
- 供应商不可用：任务失败模拟释放积分；真实状态未知时先对账。

### 19.7 错误场景 API 与 UI 映射

| HTTP | 业务错误码 | 交互要求 |
|---|---|---|
| 400 | `INVALID_DURATION` | 指出模型不支持当前秒数档位 |
| 400 | `UNSUPPORTED_MODEL_CAPABILITY` | 指出首尾帧/音频等不支持，允许切换模型 |
| 401 | `UNAUTHORIZED` | 跳转登录并保留原项目返回地址 |
| 403 | `INSUFFICIENT_PERMISSION` | 提示角色无消费或审核权限 |
| 404 | `SHOT_NOT_FOUND` | 显示镜头可能已删除，返回时间线 |
| 409 | `VERSION_CONFLICT` | 展示冲突对比，不静默覆盖 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一 key 不同请求体，不再创建任务 |
| 410 | `QUOTE_EXPIRED` | 自动弹“重新报价” |
| 422 | `INSUFFICIENT_CREDITS` | 显示缺少积分，允许降低生成参数 |
| 422 | `INPUT_REVISION_CHANGED` | 输入已变化，重新审分镜并报价 |
| 429 | `RATE_LIMITED` | 显示可重试时间，不无限轮询 |
| 500 | `PROVIDER_FAILED` | 提示失败原因及账户释放状态 |
| 503 | `PROVIDER_STATUS_UNKNOWN` | 进入对账，不自动重复扣费 |

## 20. Mock 数据方案、状态模拟与可重复演示

### 20.1 技术实现选择

优先使用 Vben 已带的 **`apps/backend-mock` Nitro Mock 服务**，实现一组与未来真实 API 兼容的业务接口，而不只是 `setTimeout()` 返回任意随机数据。

数据源设计：

```text
Mock seed JSON / TS fixtures
   ↓
Nitro Mock repository / state store
   ↓
业务模拟 service：project、insight、creative、shot、job、billing、render
   ↓
统一 API 返回
   ↓
前端 API service / Pinia Store / Vue 页面
```

建议本地 Mock 初期使用**固定种子 + 内存状态**，提供 `Reset demo` 恢复；为了支持刷新恢复，开发调试模式可选持久化到 Nitro dev storage。**不要在 localStorage 明文保存密码/Key；不要把账务状态仅放在浏览器组件中。** 如果 Mock 的 Nitro 内存重启丢失，应在页面显示“演示服务重置，数据已恢复默认状态”。

### 20.2 所有页面都应使用可再现的 Fixture

建议至少具备 4 个演示项目：

| Seed 项目 | 产品类型 | 主要创意切口 | 特意演示的难点 |
|---|---|---|---|
| `project_resume_3d` | 3D 网页简历 | PDF → 3D 网页的反常规创新 | 120 秒、多镜头、角色一致性、镜头 V1/V2/V3 |
| `project_knowledge_base` | AI 个人知识库 | 收藏很多却找不到（痛点 + 幽默） | 产品说明与真实痛点区分、30 秒故事 |
| `project_crm` | CRM/销售管理 | 跟进遗漏/协作混乱（痛点 + 结果） | 登录后功能、脱敏、演示授权和资料缺失 |
| `project_video_agent` | URL → 创意营销视频 | 网站做好了却不会推广（痛点 + 新表达） | 元产品样例、创意方向比较、图片/录屏输入 |

### 20.5 Mock 任务模拟器

建议在 Nitro 服务侧用定时推进（**服务端开发 Mock**，不通过生产 UI 假造账务事务），可设不同随机种子；自动化测试需关闭随机性并支持“立即推进到某状态”。

| 场景 | 模拟任务序列 | 验收点 |
|---|---|---|
| `success` | CREATED→QUEUED→RUNNING→DOWNLOADING→SUCCEEDED | 创建候选、结算一次 |
| `failed_before_submit` | CREATED→QUEUED→FAILED | 释放全额、无候选 |
| `failed_after_submit` | CREATED→SUBMITTED→RUNNING→FAILED | 明确失败后按测试规则释放 |
| `status_unknown` | SUBMITTED→RECONCILING→SUCCEEDED/FAILED | 不擅自追加扣费或重复提交 |
| `cancel_before_submit` | QUEUED→CANCELLED | 释放全额 |
| `cancel_after_submit` | RUNNING→CANCELLING→RECONCILING | 显示费用核对，不能立即许诺退款 |
| `duplicate_callback` | SUCCEEDED 收到两次回调 | 只创建一个候选、只结算一次 |
| `out_of_order` | 两个任务 V3/V4 乱序成功 | 都是独立候选，不自动采用最新返回 |
| `insufficient_balance` | 报价确认时报 422 | 无冻结和任务创建 |
| `quote_expired` | 下单前超时 | 提示重获报价，不扣费 |
| `stale_revision` | 剧本改后用旧报价 | 返回输入版本变化 |
| `render_failed` | 合成任务失败 | 已批准镜头不丢失，整片保留旧版 |
| `login_required` | URL→LOGIN_REQUIRED | 允许进入安全授权演示流程 |
| `missing_document` | 文档解析失败 | 允许删除、重新上传或继续部分分析 |

### 20.6 Mock 控制面板（开发环境专用）

建议在页面右上角开发工具入口加入：

- 切换项目场景与重置 Seed。
- 指定任务下一次状态 `SUCCESS / FAILURE / TIMEOUT / CANCEL / DUPLICATE_CALLBACK`。
- 模拟钱包余额 0/24/120/999 积分。
- 模拟模型支持最长 10/15/30 秒（用于证明整片 120s 仍可构成）。
- 模拟授权登录成功/失败/过期。
- 模拟脚本不足 120 秒的时长冲突。
- 模拟 V2/V3 乱序完成与 409 版本冲突。

这些控件必须由环境变量和开发权限保护，**绝不能出现在生产环境给真实客户操作**。

### 20.7 Mock 媒体资源要求

- 静态参考图优先放 `public/mock-media/`，有意义地对应各分镜，不要 15 个镜头都重复同一张默认图。
- 使用自制或明确授权的视频/音频示例，勿把随机互联网素材当客户真实产品视频。
- 要有竖屏/横屏、成功/缺失/损坏、字幕安全区和播放失败样例。
- 所有 Seed 路径应是项目仓库内可访问的相对 URL，不依赖临时外链。
- 示例素材必须能证明视频播放器控制、比对和版本选择确实可交互。

### 21.1 推荐 Store 分工

| Store | 负责数据 | 注意事项 |
|---|---|---|
| `useProjectStore` | 当前项目、路由阶段、权限、审阅状态 | 避免混入视频文件二进制 |

| `useNotificationStore` | 系统通知、任务完成提示 | 点击深链定位镜头 |

### 21.2 实时进度协议（未来 SignalR，当前模拟）

计划 .NET 8 可使用 SignalR；前端先定义统一事件订阅接口，例如：

```ts
export type JobEvent =
  | { type: 'job.status'; jobId: string; status: GenerationJobStatus; progress?: number }
  | { type: 'job.succeeded'; jobId: string; versionId?: string }
  | { type: 'job.failed'; jobId: string; code: string; message: string }
  | { type: 'wallet.updated'; availableCredits: number; heldCredits: number }
  | { type: 'shot.version.approved'; shotId: string; activeVersionId: string }
  | { type: 'render.completed'; projectId: string; renderId: string };

export interface JobEventsClient {
  subscribe(projectId: string, onEvent: (e: JobEvent) => void): () => void;
}
```

本期 `MockJobEventsClient` 通过轮询 Mock API 或 Mock 事件总线实现，未来替换成 `SignalRJobEventsClient`。事件被重复投递时按事件/任务 ID 去重；最终状态仍以服务端查询结果为准。

### 21.3 模拟任务演进代码（伪实现）

```ts
// 这是测试环境的状态推进思路，不是生产扣费实现。
async function advanceMockJob(jobId: string, scenario: MockScenario) {
  const job = await jobRepo.find(jobId);
  if (!job || isTerminal(job.status)) return;

  const next = getNextMockStatus(job.status, scenario);
  await jobRepo.updateStatus(jobId, next);
  mockEvents.publish({ type: 'job.status', jobId, status: next });

  if (next === 'SUCCEEDED') {
    await completeExactlyOnce(jobId); // 在Mock仓库里模拟事务、生成候选、结算
  }
  if (next === 'FAILED') {
    await releaseExactlyOnce(jobId);  // 避免重复流水
  }
}
```

**工程提醒**：真实后端使用数据库事务 + 幂等键 + Outbox + RabbitMQ Worker + 供应商状态核对；不要照搬前端定时器方案做收费系统。

## 22. 交互与视觉设计规范

### 22.1 总体视觉方向

- Vben 标准后台：专业、简洁、清楚状态，适用于项目、任务、账单和设置。
- Studio 创作工作台：更像一个轻量的广告导演工作室，突出大画面、图文分镜、AI 反馈和故事时间线，不要做成密集表格。
- 默认 UI 简体中文；保留 Vue Vben 国际化基础，未来可支持英文。
- 支持亮/暗主题；视频画面区尽量使用中性深色背景，以衬托预览。
- 避免使用过多彩色标签：颜色主要区分已确认、待确认、生成中、失败/风险。

### 22.2 统一状态颜色（设计 Token，不要硬编码业务组件）

| 状态语义 | 建议视觉 | 注意 |
|---|---|---|
| 已确认/成功 | 绿色/勾选 | 同时显示文字，不只靠颜色 |
| 处理中 | 蓝色/进度 | 显示具体阶段 |
| 待审核 | 橙色/提示 | 明确由谁处理 |
| 失败 | 红色/错误信息 | 附具体修复动作 |
| 过期/需复核 | 黄色/警告 | 不等于任务失败 |
| 已归档/被拒绝 | 灰色/历史 | 保留查看入口 |

### 22.3 UI 组件清单

| 组件 | 关键 Props/事件 | 用途 |
|---|---|---|
| `StudioStepper` | stage、statusMap、onNavigate | 顶部阶段进度与可访问限制 |
| `EvidenceBadge` | level、source、onOpen | 证据与推测标识 |
| `AngleCard` | concept、onSelect、onEdit | 营销切口卡 |
| `StoryBeatTimeline` | beats、duration、onResize | 剧情结构时长 |
| `StoryboardCard` | shot、revision、onApprove | 图文分镜显示 |
| `ShotEditor` | shotRevision、onSaveDraft | 编辑单镜头文字/参考图 |
| `AIRevisionChat` | messages、context、onPlan | 自然语言修改与影响范围 |
| `ShotVersionCompare` | activeVersion、candidateVersion | 同步播放与差异对比 |
| `GenerationQuoteDialog` | quote、wallet、onConfirm | 模型配置、积分授权 |
| `JobProgress` | job、onCancel | 异步进度与异常 |

| `DemoModeBanner` | enabled、scenario | 明确提示 Mock 模式 |

### 22.4 交互细则

- **每一个异步按钮**：提交后禁用重复点击、显示任务 ID/进度、允许重新进入。
- **每一个 destructive 操作**：删除、撤销授权、放弃候选、重置项目需二次确认。
- **每一个产生费用的操作**：必须展示可见费用与本次预算上限；不可把扣费藏在“继续下一步”。
- **每一个编辑器**：支持未保存提示、保存草稿、确认版、历史记录，错误保留用户原输入。
- **空状态**：告诉用户下一步做什么；例如无角色参考图时提示“可先使用默认形象，但连续性可能降低”。
- **错误状态**：不能只显示“发生未知错误”，应给行动建议。
- **媒体加载失败**：允许重试/替换/查看素材信息；禁止导致整个工作台白屏。
- **反馈透明**：AI 的洞察、价值切口、视频质量分数属于建议而非“经证实市场效果”。

### 22.5 响应式建议

- 1440px 及以上：三栏 Studio（镜头列表/主预览/AI 反馈）。
- 1024～1439px：分镜列表可折叠，AI 聊天抽屉，主预览优先。
- 768～1023px：两栏或切换面板，保留审核、修改、确认。
- 低于 768px：主要支持项目查看/审批/评论/任务状态，不强求完整精细剪辑；明确“桌面端编辑更完整”。

### 22.6 设计细节与可访问性

- 所有图标配中文文案或 tooltip；键盘 Tab 可访问主要操作。
- AI 提示区域对比度符合基本 WCAG 对比要求；避免仅靠颜色判断状态。
- 视频播放提供字幕开关与静音提醒；自动播放遵守浏览器限制。
- 输入长文案有字数反馈；项目名称超长采用省略且可查看完整文本。
- 页面路由深链刷新可恢复上下文；浏览器前进/后退不会遗失已经提交的确认。
- 保存/提交的成功消息明确区分：“草稿已保存”“版本已确认”“任务已创建”“积分已冻结”“正式成片已导出”。

- Dashboard/项目列表/新建项目。

**里程碑 M3｜高成本镜头生成闭环**

- 费用预估、余额不足、冻结/结算/释放。

- V1/V2/V3 对比、确认/拒绝/回退、版本冲突、局部修改。

**里程碑 M4｜预演与整片交付**

- 分镜低成本预演。
- 时间线快照、Mock 合成、历史成片版本、最终审核/导出。
- 全部异常场景的 E2E 覆盖，团队演示流程。

### 23.3 推荐最小可交付版本（当资源不足时）

必须坚持这些主链路，其他先降级：

`项目 → 资料采集 → 产品理解 → 3 套创意 → 剧本/时长 → 图文分镜 → 单镜头报价与生成 → 候选审核/回退 → 整片合成模拟 → 账单`

可延后：复杂时间轴拖拽、多人实时协作、全功能角色管理、真实在线播放大文件、创意质量自动评分、多语言、多平台自动发布、复杂图层编辑器。

## 25. 团队演示脚本（产品经理与研发可直接照此讲解）

**演示时长建议 10～15 分钟；演示账号、资料、金额、视频均为虚构/模拟。**

1. 打开 Dashboard，展示“3D 数字简历”项目；强调**不是操作教学视频**，要找更有吸引力的传播角度。
2. 在项目资料页上传官网、截图、录屏、说明文档，并切换“该网站需要登录”，演示安全授权入口与功能页面树。
3. 查看 AI 产品理解：功能清单、目标用户、传统 PDF 简历局限、3D 网页创新，以及**验证事实/推测痛点**标识。
4. 展示 Agent 同时找出**新奇感**与**用户痛点**，而不是所有产品都一个套路；打开 10 类传播切口库。
5. 比较 3 套创意故事；选择“静态 PDF → 互动 3D 简历”的认知刷新方向。
6. 用户要求 120 秒，系统说明 30 秒故事容量不足，选择“完整故事扩写”，得到 7 个故事节拍。
7. 打开 15 镜头图文分镜：参考图片、动作、运镜、旁白、转场、真实产品素材和总时长 120 秒。
8. 镜头 07 输入自然语言意见“纸张先破碎，再出现人物”；查看 AI 修改计划，保留不变的角色和旁白。
9. 展示生成前“8秒 × 3积分 = 24积分”，点击确认，看到钱包冻结 → 任务推进 → 完成结算。
10. V2 不满意，保留 V1 正式，生成 V3 后左右对比；采用 V3，账单能追溯每次调用。
11. 进入时间线、确认全部镜头后触发 Mock 合成，查看整片版本 V1。
12. 再把镜头 07 回退旧版，整片显示“待更新”，二次合成产生新整片版本，**旧成片不被覆盖**。
13. 最后展示任务中心、流水、模型能力矩阵与异常模拟面板。

对外展示时应明确哪些是 Mock 模拟能力，避免误导团队认为真实 AI 模型、真实登录和 FFmpeg 已实现。

## 26. 数据安全、合规和未来后端对接边界

### 26.1 当前前端 Mock 必守边界

- 不允许真正浏览或探测他人的私有网站、内网、第三方登录系统；只使用虚构演示域名及模拟页面。
- 不收集真实账号密码、不存储明文 API Key、不隐藏地调用真实外部 AI 或支付服务。
- 不使用未经授权的用户隐私录屏、图片和品牌素材作为公开演示资产。
- 所有 Mock 余额和模拟收费必须有显著标识，并只在演示环境生效。
- 下载/视频预览使用本地或明确授权的示例资源。
- 产品营销不得虚构案例、用户评价、效果数字、获得保证或隐瞒重要限制。

### 26.2 未来授权浏览器功能（后端负责实际安全）

- 用户在受隔离浏览器登录，演示域名白名单，用户主动授权。
- 会话限时，敏感操作禁止，限制浏览器网络范围（含内网/本机/云元数据地址及跳转）。
- 默认只读与模拟数据；采集与模型输入前脱敏；权限最小化和操作审计。
- 若以低权限测试账号方式接入，凭据在后端安全托管，禁止传到模型上下文或日志。
- 所有浏览器操作、隐私资料保留与删除规则须产品和法务明确。

### 26.3 未来账务/任务服务（后端职责）

- .NET 8 / PostgreSQL 实施余额、冻结、结算事务；金额变更采用可追溯不可变流水。
- 幂等键、唯一索引、Outbox + RabbitMQ、供应商任务核对，防止重复扣费与重复生成。
- 视频生成 Worker（Python/其他）与前端解耦；MinIO 保存引用媒体，签名上传下载。
- SignalR 只传事件通知，状态仍以服务端记录为准；事件包含 projectId/jobId/版本标识。
- FFmpeg/Remotion 运行在受控合成服务，不在浏览器执行服务端视频合成。
- 对于视频模型是否支持延展、尾帧、编辑等，不做跨供应商能力的假定。

### 26.4 技术集成分层建议

```text
[Vue Vben Admin + Element Plus]
   ├─ 标准后台：项目/素材/任务/账单/配置
   └─ Studio 全屏工作台：产品理解/创意/分镜/预演/镜头/成片
          │
          ▼
[统一 TypeScript API Service + Job Event Client]
          │
          ├─ 当前：Nitro Mock API + Mock 状态模拟器
          │
          └─ 未来：ASP.NET Core 8 API + SignalR
                       ├─ PostgreSQL（版本/任务/订单/审计）
                       ├─ Redis（缓存、并发限流）
                       ├─ RabbitMQ（异步任务）
                       ├─ MinIO（录屏、参考图、视频、成片）
                       ├─ Python + LangGraph（产品理解/创意/分镜 Agent）
                       ├─ 模型适配：Qwen / 豆包 / 可灵 / Seedance / TTS
                       └─ FFmpeg + Remotion（最终渲染/动画）
```

该图仅供前端团队理解未来接口归属；**此阶段不要求实施后端服务**。

## 27. 性能、质量、工程规范与交付物

### 27.1 性能原则

- 首屏优先只加载项目卡片与当前必要数据，不一次性加载 15～100 个高清视频文件。
- 图片采用缩略图与延迟加载；视频按需预加载 metadata，不同时自动播放全部镜头。
- 大列表采用分页或虚拟列表，避免全量渲染。
- AI 对话、时间线拖拽、输入防抖；异步保存与版本确认明确区分。
- 释放不再使用的 `URL.createObjectURL()`，避免长时间编辑内存增长。
- 视频播放器卸载时停止播放与定时器，切换项目后解除订阅，防止状态串台。

### 27.2 代码风格与分层

- TypeScript `strict`，关键业务对象禁止 `any` 泛滥。
- 不在 Vue 单文件组件中写复杂的扣费、审核状态机与 Mock 数据写入；使用 Service / Store / Composables。
- 函数以业务意图命名，如 `approveShotVersion()`、`requestRegenerationQuote()`。
- 不使用随机 ID 作为审核/账务对象主键模拟以致测试不可重复；可用固定种子、单调序列或 UUID，E2E 有稳定选择器。
- 客户反馈、AI 建议、审核动作要有日志记录和版本引用。
- UI 文案集中在 locale 文件，业务枚举集中定义，保证未来国际化。
- 组件不得直接依赖 Nitro 或特定模型 API，隔离在 API Service 与能力配置里。

### 27.3 安全交互与体验

- 对外链接打开前明确目的，不在同页面偷偷提交用户数据。
- 录屏和截图可能包含敏感信息；在采集确认与视频导出前提供“是否需要打码”的检查项。
- 字幕/旁白禁止包含未核实功效或涉嫌侵权的品牌素材。
- 支持允许/禁止使用的广告表达清单；用户可以选择保守或大胆视觉表现，但不能选择虚假事实。

### 27.4 交付物列表

**代码交付**：

- 可运行的 Vben `web-ele` 项目业务实现。
- 独立 Studio 布局、页面路由、组件与设计 Token。
- Mock API、Seed Fixtures、任务状态模拟器、模拟钱包账务。
- Vitest 与 Playwright E2E 测试，覆盖主要成功与异常链路。

**文档交付**：

- `README`：安装、运行、账号、Mock 重置、常见问题。
- `API_CONTRACT`：前端请求契约与状态枚举。
- `MOCK_SCENARIOS`：演示场景与开发调试操作。
- `COMPONENTS`：关键业务组件 props/events 和示例。
- `CHANGELOG`：每次迭代完成的功能和遗留项。
- 页面说明或 Figma/Excalidraw 设计稿（如团队有设计人员）。

### 27.5 Definition of Done

一项前端需求完成须满足：

1. 能从实际路由进入，不只在 Storybook 或静态图片里存在。
2. 能从 Mock 服务读取并修改业务状态，刷新行为符合要求。
3. 空/加载/成功/失败/过期/无权限等分支有明确 UI。
4. 与相邻步骤的数据引用一致，保存草稿和确认版本逻辑正确。
5. 不会因为重新生成自动覆盖正式镜头或重复扣费。
6. 有必要的单元/端到端测试、中文文案和代码审查。
7. 产品经理能按第 25 节演示脚本实际操作。

## 附录 B：质量评价与真实市场验证（未来功能预留）

建议未来收集实际数据时至少分开：

- **内容创意质量**：用户盲评、是否与真实产品匹配、差异化程度、叙事连贯性、品牌一致性。
- **交付质量**：每分钟成片的有效素材生成量、失败重试率、人工修改次数、整片交付时间与成本。
- **营销表现**：各渠道真实播放、3 秒留存、完播率、点击、注册/试用、后续转化（需授权接入且数据来源可追溯）。
- **付费验证**：独立开发者、小 SaaS 等用户群的真实付费与复购，而非仅靠预设演示数据证明市场竞争力。

**原则**：视频漂亮 ≠ 有效营销；播放量高 ≠ 真实付费。前端 Mock 可以展示指标占位，但必须清楚标识“演示数据/尚未接入实际投放”。

---

**本期交付目标总结**：让团队在真实 AI 与后端尚未接入前，就能通过浏览器完整体验：**输入产品资料 → 发现产品的独特传播价值 → 选择创意故事 → 适配 120 秒长片 → 审核图文分镜 → 逐镜头报价与生成 → AI 局部修改 + 版本回退 → FFmpeg 合成模拟 → 成片审核与账务追溯**。

> **真正的产品壁垒**，不是表单有多少步、镜头能生成多长，而是 Agent 能否发现客户自己没有想到的传播价值，同时让整个高成本视频生产流程**可预期、可修改、可追溯、可控制预算**。

### C.1 每次 AI 输出应有“可解释性摘要”

对于**为什么推荐这个传播切口**，页面至少展示：

- 关联的已确认产品功能是什么；
- 目标用户的具体场景是什么；
- 触发了何种观众情绪或认知刷新；
- 视频可以通过什么画面表达；
- 哪些内容是已有证据、哪些仍是推测；
- 为什么不优先使用其他切口。

例如产品 3D 网页简历：

> **推荐切口**：旧方式与新方式的反差（静态 PDF → 可互动 3D 网页）。  
> **理由**：创意展示形式本身具有较直观的视觉差异，适合快速画面呈现。  
> **辅助价值**：个性表达、作品与经历展示。  
> **真实性风险**：不能直接声称使用后简历通过率提升或招聘成功率提高。

### C.2 “像参考视频一样吸引人”的设计要求

前端要允许 AI 创意以“高吸引力短视频语言”表达，支持以下视觉参数但不强行每条视频使用全部参数：

- 开头 3 秒强钩子、悬念、反差；
- 夸张但保持品牌一致的 3D 卡通形象；
- 创意拼贴、动态大字、场景切换、画面缩放；
- 与剧情相关的音效、背景节奏、视觉隐喻；
- 情绪发展和故事反转；
- 产品在合适时刻自然露出，而不是首屏硬广；
- 真实产品画面或 Logo 有清晰可辨、准确无错字的呈现；
- 人物、场景、风格在多个镜头中一致。

这些是**创意风格可编辑参数**，而非“用户给个 URL 就承诺可复刻任何参考视频”；生成质量依赖素材、模型、制片质量和预算。

### C.3 前端 AI 修改消息标准格式（建议）

```ts
export interface AiRevisionSuggestion {
  id: string;
  projectId: string;
  shotId?: string;
  userFeedback: string;
  intent: 'SCRIPT_TEXT' | 'MOTION_ACTION' | 'CHARACTER_EXPRESSION'
    | 'GLOBAL_CHARACTER' | 'NARRATION_AUDIO' | 'TIMELINE'
    | 'ASPECT_RATIO' | 'STRUCTURE' | 'OTHER';
  scope: 'TEXT_ONLY' | 'SINGLE_SHOT' | 'MULTIPLE_SHOTS' | 'GLOBAL';
  rationale: string;
  proposedChanges: Array<{
    field: string;
    before: unknown;
    after: unknown;
  }>;
  preservedFields: string[];
  affectedShotIds: string[];
  requiresNewImage: boolean;
  requiresNewVideo: boolean;
  requiresRequote: boolean;
  uncertainties: string[];
  status: 'PROPOSED' | 'ACCEPTED' | 'REJECTED' | 'APPLIED';
}
```

**用户体验**：AI 对话提出改动 → 前端展示可审阅差异 → 用户选择“应用修改” → 创建新的 ShotRevision → 若需要视频生成则另行报价。用户说一句话并不等于默许收费。

## 附录 D：商业竞争背景与前端产品表达

### D.1 市场背景（作为产品设计依据，而非已验证市场报告）

此前讨论的判断是：**AI 通用视频生成与普通 URL-to-Video 已是红海；针对独立开发者/小型 SaaS 深度理解产品并提出新颖创意的能力，仍有待验证的细分竞争机会。**

前端的产品表达不能落入“只需输入网址，一键保证爆款”的夸张话术；更合理的核心文案是：

> **从一个产品网址，发现值得传播的故事。**  
> AI 先理解产品和用户，再寻找真正有吸引力的价值切口，提供可以逐阶段审核、逐镜头修改的视频制作流程。

### D.2 预留的套餐与商业化界面

目前积分模拟计费优先。未来可以支持：

- 创意分析/图文分镜单独交付（不生成视频）。
- 单条生成或按镜头视频生成额度收费。
- 30/60/120 秒不同套餐、不同分辨率/模型质量档位。
- 订阅包月、团队额度、余额充值、费用分析。
- 多平台版本、功能版本更新推广、持续创意迭代。

此前讨论过的 **¥39～99/条简单视频、¥299～999/条真实演示服务、¥99～299/月订阅**均只是早期市场测试假设，**不能作为产品正式定价事实**；本期前端仅显示模拟积分和“套餐规划中”。

### D.3 对产品效果的验证方式（未来运营，不属于 P0）

- 使用 10 个不同类型产品 URL 做竞品对照，避免只拿一个成功样例当结论。
- 分别评价产品理解准确、痛点真实、创意新颖、视频成片质量、成本和修改量。
- 向潜在客户验证付费意愿；此前设想的“10 人中 3 人真实付款”可作为初步实验门槛，而非市场统计定律。
- 收集创意与实际营销转化之间的关联，但需要真实授权的播放/点击/注册数据。

在 Mock UI 中可以设计“效果分析”的占位页，但必须写“真实渠道数据尚未接入”。
